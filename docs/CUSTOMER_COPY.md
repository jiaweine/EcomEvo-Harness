# EcomEvo 客户端最终文案

这份文档是客户可见文案的源事实。新增或修改客户端页面时，优先使用这里的表达，不要把内部技术名词直接暴露给客户。

## 1. 品牌与顶部栏

- 产品名：`EcomEvo`
- 产品副标题：`业务服务助手`
- 搜索框：`搜索办理记录或业务入口`
- 导览：`使用帮助`
- 资料入口：`我的资料`
- 处理方式：`处理方式`
- 系统入口：`系统状态`

不要使用：`Decision Runtime`、`认知引擎`、`Provider`、`Runtime 插件`。

`业务办理`

- `最近办理`
- `刷新`

### 新建

- `新建办理`

## 3. 首页

### 主标题

`您好，今天想处理什么？`

### 副标题

`提交问题和相关资料，我们会帮您核对信息、说明当前结果，并告诉您下一步怎么做。`

### 四个快速入口

1. `商品问题`
   - `核对商品信息、素材或资质`
2. `商家认证`
   - `查看主体、授权或认证问题`
3. `售后处理`
   - `处理退款、履约或责任争议`
4. `风险问题`
   - `核对异常交易或账户问题`

### 支持资料

`支持图片、视频、音频、文档和表格`

不要使用：`多模态输入`、`目标与证据`、`自适应规划`、`并行查证`、`验证门禁`、`恢复演进`、`Event Sourced`。

## 4. 首页服务概况

标题：`服务概况`

建议字段：

- `服务状态` — `正常` / `暂时繁忙`
- `最近办理` — 显示真实的最近办理数量
- `待您确认` — 显示真实待确认数量，无数据时不伪造
- `资料支持` — `图片、文档、表格等`

辅助文案：`信息会自动保存，您可以随时回来继续。`

不要使用：`OPERATIONS SNAPSHOT`、`RUNTIME`、`ACTIVE PLUGINS`、`AUTHORITY`、`契约有效`。

`目前没有需要您确认的事项。`

## 12. AI 回复结构

回复默认按客户阅读顺序组织，而不是按模型推理过程组织。

### 当前结果

`我们已经核对了您提交的信息，目前……`

### 还需要您补充

`请补充品牌授权书首页，图片需完整清晰。`

只有确实缺资料时出现。

### 判断依据

`订单记录显示……；物流记录显示……`

只放与结论直接相关的信息。

### 下一步

`补充资料后我们会继续处理，您无需重新提交问题。`

或者：

`如果您确认继续退款，请点击右侧“待确认”。`

## 17. 错误与异常

不要只显示错误码。

推荐：

- `暂时无法加载，请稍后重试。`
- `资料上传失败，请重新上传。`
- `当前服务暂时繁忙，请稍后再试。`
- `这项操作没有成功，业务状态没有发生变化。`

如果有恢复方式，必须告诉客户下一步。

## 18. 禁用词表

普通客户界面禁止直接出现：

`Runtime`、`Agent`、`Plugin`、`Planner`、`Verifier`、`Trace`、`Event Trace`、`Event Sourced`、`Provenance`、`Authority`、`Contract`、`Generation`、`Sandbox`、`Model`、`Provider`、`Belief State`、`Harness`、`Graph-of-*`、`Recursive Agent`、`Cognition`、`Execution Plane`、`Safety Plane`。

如果内部概念必须展示，先转换成客户能理解的业务结果或动作。
