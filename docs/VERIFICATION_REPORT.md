# EcomEvo 再验证报告

## 结论

本轮不是只重跑已有测试，而是围绕证据误判、并发副作用、多模态一致性、长文档、真实网络层、MCP、进程中断和前端场景状态做了反例测试与修复。

最终干净交付前执行：

- 自动化测试：64 项全部通过。
- 产品 E2E smoke：售后任务 → 上传证据 → Runtime → 待确认操作 → 确认执行，通过；事件 hash chain 有效。
- 实际 Uvicorn：`/api/health`、首页、前端 JS、`/docs` 实际 HTTP 200。
- 实际 WebSocket：收到 message.accepted、连续 progress、answer.ready。
- 并发消息：5 组同任务双请求，每组恰好一个 200、一个 409，跨请求任务租约生效。
- Python compileall、前端 `node --check`、CLI `--help` 通过。

## 本轮发现并修复的主要问题

1. **资料不足仍可能生成操作**：工具成功被误当作业务证据。改为证据完整性硬条件。
2. **场景选择只停留在 UI**：后端可能按 general 判断。场景现在进入任务上下文；已有内容跨场景快捷入口会新建任务。
3. **重复确认可能重复副作用**：动作确认改为 SQLite 原子 compare-and-set；并发第二次确认返回 409。
4. **附件可跨任务引用**：附件绑定改为原子归属校验；上传必须属于一个已有任务。
5. **事件写入只靠进程内锁**：事件追加改为 SQLite `BEGIN IMMEDIATE`，多进程序号/hash chain 压测通过。
6. **checkpoint 使用 pickle**：改为 JSON 持久化边界。
7. **WebSocket 断线/请求失败交互不完整**：加入重连、状态重取、乐观消息回滚。
8. **MCP 连接实现不完整**：补现代请求头、JSON/SSE 结果、tool schema/header 参数与旧协议初始化/Session fallback；补业务动作映射和只读企业证据工具。
9. **多模态事实进入最终回答但没进入复核**：视觉/音频/扫描 PDF 事实现在先进入证据链，再做业务验证。
10. **低置信度视觉读取也可能当证据**：加入语义读取置信度门槛；模糊读取 fail closed。
11. **同一多媒体每轮重复识别**：语义事实按附件指纹持久缓存，并带 schema version；后续轮次复用，避免重复费用和结果漂移。
12. **Gemini 扫描 PDF/大媒体链路缺失**：补 PDF 文档能力、Files API 路径、流式上传、处理状态和远端临时文件清理。
13. **连续对话实际上不连续**：同任务历史用户说明和既有资料自动进入后续轮次；此前系统回复只用于语言承接，不提升为证据。
14. **所谓递归复核只是平铺并行**：加入条件触发的第二层交叉复核，并记录 parent/depth/children。
15. **任务记忆只写不读**：完成案例的风险项会作为后续同场景检索提醒，重启恢复，但明确不能作为本轮证据。
16. **失败改进写库但不生效**：通过门禁的 planner patch 立即应用、重启恢复、同类去重。
17. **附件 hash 记录了却不复核**：每轮执行前重新核验源文件 SHA-256；视频派生关键帧也单独校验。
18. **长日志/PDF/Excel 后半段搜不到**：展示文本和服务端检索索引分离；扩大受控检索范围，表格扫描后续行。
19. **资产 API 泄露内部路径/检索索引**：浏览器响应移除绝对路径、search_text、关键帧路径和内部语义缓存。
20. **模型文本能绕过后端状态**：证据不足时强制使用服务器受控结论，外部模型不能把 incomplete 说成“通过”。
21. **进程崩溃后前端永久处理中**：加入跨进程可续租任务 lease；过期后恢复为明确的 answer.error，允许继续任务。
22. **泛相关证据导致具体问题假通过**：问“治愈功效”必须有功效声明；问“授权”必须有授权材料；普通“风险”关键词不再被当作风险强证据。
23. **WebSocket 运行依赖未显式声明**：新增 `websockets` 依赖，并加入真实网络 live smoke。
24. **错误详情可能直接回客户**：客户事件改为通用错误说明，详细异常留服务日志；MCP 业务动作失败也不回传内部异常文本。

## 已验证但不是“真实线上调用”的部分

- OpenAI/DeepSeek/Qwen/Doubao/Claude/Gemini 适配器的请求结构和错误分支由单元测试/MockTransport 验证；没有用户的真实 API Key，因此没有冒充线上厂商调用通过。
- MCP 现代/legacy 路径由协议级 mock 验证；真实企业 MCP 仍需用目标企业地址、鉴权和工具 schema 做接入验收。
- 当前执行容器无法从外部包索引完成“全新 venv 在线安装”，因此该项未伪报通过。项目已在 requirements/pyproject 固定 Pillow `<12` 并显式加入 WebSocket 依赖。
- 当前容器此前对 Chromium 访问 localhost 有管理策略限制，因此没有把真实浏览器 GUI E2E 标记为通过；真实 HTTP + WebSocket 网络链已通过。
- EComAgentBench、τ³-bench Retail、TUA-Bench 指标没有在本轮重新跑数据集，不把本地测试当 benchmark 复现。

## 生产前仍需由部署方补齐

- 当前按单企业工作区部署；正式公网环境应接企业 SSO/API Gateway，不应裸露未鉴权 FastAPI。
- 真实模型 Key、配额、超时、区域网络与数据合规需要按客户环境验收。
- 真实退款/下架/冻结等 MCP 工具需使用下游幂等键、权限最小化和企业审计策略。
